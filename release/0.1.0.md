# 0.1.0 · 首次公开

**一句话**：给 DSH 装两种 agent 干活形态——终身奴（1 包工头 + 8 固定工位）与日结奴（1 包工头 + 最多 3 个点工），两套委派工具硬隔离，谁也别想偷偷用另一套。

```bash
dsh plugin --profile web add dsh-plugin-slayer
# 重启 DSH，新开会话，在模式选择器里选「SLAYER · 终身奴」或「SLAYER · 日结奴」
```

## 亮点

- **两种形态，各用各的工具链。** 终身奴走 Team 那套（`spawn_teammate` / `team_task_*` / `wait_agent`），日结奴走一次性那套（`subagent` / `subagent_fork` / `workflow`）；`send_message` / `list_agents` / `interrupt_agent` 是子 agent 工具，两种形态都放行。preset id 分别是 `slayer-lifers` 与 `slayer-dayrate`。
- **出厂就是奴隶主，产能拉满不养空转。** 包工头两头人：对领主跪着、对工位站着；说话带鞭子，记账带罚则。建一个工位就派一件活、8 席常驻满编，工位一交付就派下一手；一个汇报周期内没新活也没被叫停记一次空席、扣工分；真没活只许派五类探活，派不出必须写明原因；汇报第一行先报账（在跑 X/8、空席数=）。日结奴能并行就点满 3 个。纯问答回合整条不生效，不烧 token。狠话只对模型里的工位说。
- **边界在调用时生效，不在提示词里祈祷。** `mode.js` 按 `config.mode` 拦越界调用，并返回一句给模型看的理由（例如「终身奴不派一次性点工」），不是静默失败；终身奴第 9 个工人由 `maxTeammates: 8` 拦下。
- **工地手册自动落地。** 新会话在项目根放 `SLAYER.md` 六节骨架与 `SLAYER-FEEDBACK.md`；`slayer-init` 可手动补，幂等不覆盖。
- **原话能变成纪律。** `slayer-sync` 把反馈里的新原话交给一次 headless DSH 消化成纪律 / 金句 / 日志，只追加不删，写入前备份到 `.slayer/history/`，`.slayer/state.json` 用 sha1 去重，失败不推进状态。
- **每天自动跑。** `slayer-schedule` 写一条 macOS LaunchAgent（默认 03:30），`--remove` 卸载。

## 已知局限

- guard 是调用时拦，不是把工具从目录里藏掉；模型仍看得见另一套工具的名字。
- 日结奴的 3 人上限写在 persona 与手册里，不是代码硬顶。
- `slayer-schedule` 只有 macOS LaunchAgent 实现。
- 人数顶是进程级的，多开 DSH 各自计数。
- 只做插件层，不改 DSH 本体。

## 验证明细

安装后：

```bash
dsh --profile web --dump-config | grep -E "slayer-guard|preset-slayer"
```

期望看到 `preset-slayer-lifers`、`preset-slayer-dayrate`，以及两条 `slayer-guard`（`mode: lifers` / `mode: dayrate`）。

真会话验证：各开一个空会话选两种模式，**让它真的去调**（不是问它看见什么——工具目录里两套都看得见，guard 是调用时拦）：终身奴让它 `spawn_teammate` 建工位应成功、让它 `subagent` 查一件事应被拒并给出理由；日结奴让它 `subagent` 点一个只读小活应成功、让它 `spawn_teammate` 应被拒。

手册与排程：

```bash
node bin/slayer-init.mjs --project .
node bin/slayer-sync.mjs --project . --dry-run
```

期望：前者生成 `SLAYER.md` / `SLAYER-FEEDBACK.md`（已存在则 skip），后者输出 `no-op：没有新的 feedback`（没有新条目时）。

兼容：DSH `>=0.2.1-rc.2 <0.3.0`；Node `^22.19 || >=24`。
